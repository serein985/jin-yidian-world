# “近一点”个性化动物世界设计

日期：2026-10-31

## 1. 产品目标

将当前固定三动物原型升级为面向比赛展示的个性化动物世界。用户可以选择预设动物，也可以上传自己的画作创建原创动物；每只动物拥有独立详情页、多点触摸动画、每日喂养值、优惠券进度、记录和日历事项。应用支持本地身份与多种视觉登录样式，并可通过园区二维码直接打开对应动物。

视觉目标是“可爱角色 + 高品质游戏画面”，不是粗线条插画或低质量 3D。首页和叙事层采用电影感 2.5D，预设动物详情页使用真实可旋转缩放的 Three.js 3D 舞台；原创画作保留二维原图，通过多个触摸点产生轻量局部动画。

## 2. 产品边界

### 包含

- 可切换的三种本地登录视觉样式。
- 本地昵称和头像身份。
- 八种预设动物。
- 上传原创画作并创建任意动物。
- 自由添加、删除和排序首页动物，数量可变。
- 单动物详情页。
- 预设动物的可旋转缩放 3D 舞台。
- 原创画作的多个触摸点及五种动画效果。
- 每只动物独立的喂养值、每日奖励和优惠券。
- 三种原有优惠券权益，以及新增的纪念照片券和园区饮品券。
- 跨动物日历、预约、页面内提醒和到期高亮。
- 应用内二维码扫描。
- 园区二维码直达指定动物详情。
- 本机持久化、异常降级和移动端性能优化。
- 新公网仓库发布、新二维码和旧 GitHub 项目删除。

### 不包含

- 真实短信、微信、OAuth 或账号服务。
- 园区后台、真实库存、支付或生产级核销。
- 不同设备之间同步原创画作和互动记录。
- 用户自行上传 3D 模型、骨骼或逐帧动画。
- 浏览器关闭后的系统级通知。
- 照片级写实动物或重型开放世界。

## 3. 首次进入与本地登录

### 登录样式

首次进入显示三种可选择、可随时切换的视觉身份样式：

1. **入园门票**：暖米色纸张、票根编号、圆形头像和检票印章。
2. **饲养员工作证**：深绿证件、照片框、岗位标签和挂绳视觉。
3. **极简头像**：柔和留白、单一色块和昵称首字。

### 身份规则

- 用户输入 1 至 12 个字符的昵称。
- 头像由预设色板和动物图形组合，不上传真人照片。
- 身份样式只改变视觉，不影响数据。
- 本地只保留一个主要游客身份。
- 资料页可以修改昵称、头像和登录样式。
- 登录不请求密码、短信或第三方授权。

## 5. 原创动物创作台

### 图片上传

- 支持 PNG、JPG 和 WebP。
- 原始文件上限为 12MB。
- 上传后在浏览器内压缩到最长边不超过 1600px，并生成 WebP 或 JPEG 预览。
- 用户可以选择保留透明背景或使用系统主题背景。
- 图片二进制保存到 IndexedDB；元数据保存到主状态。

### 动物资料

用户填写：

- 动物名称，1 至 12 个字符。
- 物种名称，1 至 12 个字符。
- 主题色，从六套精细配色中选择。
- 优惠券类型，从五种权益中选择。
- 喂养值门槛，在 `20` 至 `100` 之间以 `5` 为步长选择。

### 触摸点编辑

- 用户点击画作设置触摸点。
- 触摸点保存相对 `x / y` 坐标，不依赖屏幕尺寸。
- 每个动物最多 12 个触摸点。
- 每个触摸点可设置 0 至 6 个字符的提示文字。
- 每个触摸点只能选择一种主动画：
  - 局部弹跳
  - 摇头
  - 闪烁
  - 冒爱心
  - 短动画
- 编辑器支持选择、拖动、删除和重新指定动画。
- 保存前必须至少在画作上添加一个触摸点。

### 动画演示

- 触摸点触发局部裁切层在图上的动画，不要求用户拆分图层。
- “局部弹跳”对触摸点附近的圆形图片切片做短距离上下弹跳。
- “摇头”通过透视位移表现短促摆动。
- “闪烁”通过亮度与透明度脉冲表现。
- “冒爱心”在触点附近产生有限粒子。
- “短动画”组合轻微缩放、旋转和光晕。
- 动画长度控制在 420 至 900ms，避免阻塞连续互动。

## 6. 首页与收藏管理

### 首页构图

- 首页不采用普通卡片网格。
- 当前选中动物位于电影感场景中央，使用高质量 2.5D 光效、景深和粒子。
- 其他动物排列在下方带透视的收藏轨道中。
- 用户左右滑动或点击切换当前动物。
- 顶部展示昵称、日历、扫码、券包和资料入口。
- 底部展示当前动物进度和“进入它的世界”主操作。

### 增删与排序

- 点击“添加动物”选择预设动物库或原创动物创作台。
- 同一预设动物不可重复添加。
- 原创动物可以添加多个，并生成唯一 ID。
- 删除动物需要二次确认。
- 删除原创动物时同时删除其画作和触摸点。
- 删除动物会删除该动物的喂养值、互动记录和券记录。
- 用户可通过拖动手柄或上下移动按钮调整顺序。
- 用户至少保留一只动物；删除最后一只时进入空收藏册引导。

## 7. 动物详情页

### 页面结构

- 顶部返回、动物名称、日历、券包。
- 中部主舞台：预设动物使用 3D，原创动物使用图片触摸点舞台。
- 舞台下方显示物种、今日状态和轻提示。
- 数据区显示独立喂养值、门槛和券进度。
- 操作区包含抚摸、投喂和“今天记录”。
- 历史区可展开查看该动物所有记录。

### 预设动物 3D 舞台

- 使用 Three.js 实时渲染。
- 支持单指旋转、双指缩放和自动缓慢转台。
- 角色具有呼吸、眨眼、视线跟随和触摸反应。
- 灯光包含主光、轮廓光和环境补光。
- 地面具有接触阴影和柔和反射。
- 使用毛绒材质表现：柔和粗糙度、边缘光、细微纹理和高光。
- 后处理只使用轻量 Bloom、暗角和色调映射，不依赖重型景深。
- 仅当前详情页加载 3D，离开页面立即释放渲染资源。
- 设备像素比上限为 `2`，低端设备按 `1.25` 降级。
- WebGL 不可用时回退到同角色的高清静态插画。

### 原创动物舞台

- 画作以完整比例显示，优先保留用户构图。
- 透明画作使用柔和光晕和接触阴影托底。
- 触摸点编辑模式使用可见标记；浏览模式只显示短暂波纹提示。
- 点击触摸点触发对应动画，不弹出阻挡画面的对话框。
- 连续点击有节流，避免动画堆积。

## 8. 喂养与优惠券

### 每日规则

- 每只动物每天首次抚摸奖励 `+1`。
- 每只动物每天首次投喂奖励 `+4`。
- 每只动物每天只能成功投喂一次。
- 喂养值、奖励日期和券状态均按动物独立保存。
- 自定义动物的喂养值门槛由创建时设置。

### 优惠券类型

预设动物使用配置权益。原创动物创建时从以下权益中选一种：

- 动物周边 9 折券。
- 园区餐饮满 50 减 10 元。
- 互动体验减 10 元。
- 纪念照片减 8 元。
- 园区饮品买一赠一。

### 券生命周期

- 未达门槛时显示进度。
- 达到门槛自动解锁券并生成核销码。
- 券状态为可出示、已核销。
- 核销需要二次确认。
- 核销完成后不可逆，刷新后继续显示已核销。
- 券包展示所有动物的券，可按状态筛选。

## 9. 日历、预约和提醒

### 日历

- 默认展示当前月份。
- 支持前后切换月份和返回今天。
- 日期标记区分互动、投喂、券、预约和提醒。
- 选中日期后显示当天所有动物的事件时间线。
- 今天使用高亮边框。
- 未来三天存在预约时显示“即将到来”提示。

### 新建事项

用户可以为任意动物添加：

- 预约：日期、时间、标题、动物、备注。
- 提醒：日期、标题、动物、备注。
- 时间可留空，表示全天事项。

### 页面内提醒

- 当天事项在登录后和首页展示提醒卡。
- 已超过预约时间的未完成事项标记为“已到期”。
- 用户可以标记完成或删除。
- 页面打开期间每分钟重新计算到期状态。
- 不使用系统通知或 Service Worker 后台唤醒。

## 10. 扫码与路由

### 外部扫码

- 园区二维码使用 `/index.html?animal=<animal-id>&source=park` 或根路径查询参数。
- 应用读取 `animal` 参数后直接打开对应动物详情。
- 动物不存在时显示“没有找到这个园区伙伴”，并提供返回收藏册。
- 扫码入口必须带有 `source=park` 时记录来源，用于日历展示“园区扫码”。

### 应用内扫码

- 顶部扫码按钮打开全屏相机扫描层。
- 优先使用浏览器 `BarcodeDetector`。
- 不支持时使用 `jsQR` 对视频帧进行识别。
- 识别园区 URL 后解析 `animal` 参数并进入详情。
- 无法识别时显示重试、手动输入编号和关闭操作。
- 相机权限被拒绝时直接展示说明和手动输入。
- 离开扫描层时停止所有媒体轨道。

## 11. 本地数据与存储

### 主状态

版本化键：`jin-yidian:v3:world`

主状态包含：

- 数据版本。
- 本地身份。
- 用户选择的登录样式。
- 动物档案列表与排序。
- 每种动物的喂养和券状态。
- 日历事件。
- 当前选中动物 ID。
- 提醒完成状态。

### 图片存储

- IndexedDB 数据库：`jin-yidian-assets`
- Store：`animal-artwork`
- Key：原创动物 ID
- Value：压缩后的 Blob、MIME 类型和更新时间。

### 降级

- `localStorage` 不可用时，当前页面会话继续可玩。
- IndexedDB 不可用时，原创图片只在当前会话保留。
- 图片损坏或读取失败时显示缺失画作占位，不删除动物记录。
- 主状态损坏时逐项清洗；无法清洗时创建空收藏册。
- 旧版 `jin-yidian:v2:*` 数据不迁移，避免将固定动物模型误映射到新收藏结构。

## 12. 技术架构

### 依赖

- React + TypeScript + Vite。
- Three.js 和 React Three Fiber 渲染 3D。
- Drei 提供相机和 Orbit Controls。
- `jsqr` 作为二维码扫描回退。
- Lucide React 提供界面图标。
- Canvas 用于图片压缩、局部动画切片和静态回退。

### 模块边界

- `world-model`：身份、动物档案、收藏顺序、喂养值与事件领域函数。
- `asset-store`：原创画作的读取、保存和删除，可注入内存实现进行测试。
- `calendar-model`：月份网格、事件聚合、到期状态。
- `qr-route`：URL 构造与二维码解析。
- `animal-3d`：模型配置、材质、灯光、控制和动画，不直接修改业务状态。
- `touchpoint-editor`：触摸点相对坐标、动画类型和编辑器操作。
- `screen-router`：首页、详情、创作台、日历、券包、资料和扫描界面。

### 导航

- 使用浏览器 History API 与查询参数，不引入完整路由框架。
- 页面刷新后可以根据 URL 恢复详情或扫码入口。
- 首页和普通功能使用内部状态切换，不产生无效历史记录。

## 13. 错误与边界

- 拒绝相机权限：显示手动输入码和关闭入口。
- 摄像头不可用：不显示空白视频层。
- 未知园区动物：显示明确错误，不自动创建预设动物。
- 上传格式不支持：提示支持的格式和大小。
- 图片压缩失败：允许使用原始图片但提示可能较慢。
- 超过 12 个触摸点：阻止继续添加并提示上限。
- 触摸点位于画作边缘：自动限制在可操作范围。
- 3D 加载失败：切换为静态角色画面。
- 页面切到后台：停止 3D 渲染循环和相机轨道。
- 重复核销：拒绝操作并保留第一次核销时间。
- 删除最后一只动物：进入空收藏册，不允许调用空详情。

## 14. 视觉与性能标准

- 角色必须保持参考图的圆润、大眼、低饱和腮红和柔焦毛绒感。
- 不使用粗糙几何贴纸、廉价渐变球、默认表情符号或未处理的系统组件。
- 3D 模型使用统一风格但具备物种差异，不呈现低多边形棱角。
- 首页和详情页使用定制背景、细颗粒、柔和体积光与分层景深。
- 关键转场为 280 至 560ms，并尊重减少动态效果设置。
- 3D 场景目标在中端手机维持至少 30fps。
- 首页不加载全部 3D 模型。
- 用户画作在首页和收藏轨道中使用缩略图，不重复解码完整图片。
- 触控目标至少 `48 x 48` CSS 像素。
- 桌面端保持居中的移动画布，页面元素不拉伸变形。

- 首页动物轨道可切换、添加、删除和排序。

## 16. 发布与历史清理

- 最后删除旧仓库 `serein985/jin-yidian-habitat`。
- 删除旧仓库前必须确认新公网地址返回 `200`，CSS、JavaScript 和核心交互正常。
- 旧二维码不得继续作为比赛交付物。

## 17. 验收标准

- 用户可选择三种登录视觉样式并创建本地身份。
- 首页默认三只动物可删除，并可追加任意数量的预设或原创动物。
- 预设动物库至少包含八种动物。
- 用户可以上传自己的画作，添加最多 12 个触摸点，并为每个点选择五种动画之一。
